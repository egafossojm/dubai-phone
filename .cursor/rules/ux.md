 # UX Rules

## 1. UX Philosophy

The application is business software.

Prioritize:

1. Speed
2. Clarity
3. Predictability
4. Reliability
5. Accessibility

Avoid unnecessary decoration.

---

# 2. Language

User-facing text must be French.

Use terminology appropriate for Cameroon.

Currency:

FCFA

---

# 3. Navigation

Primary navigation should expose the main operational areas:

- Tableau de bord
- Ventes
- Produits
- Stock
- Achats
- Fournisseurs
- Clients
- Crédits
- Retours et garanties
- Rapports
- Administration

Navigation visibility should respect permissions.

---

# 4. POS UX

The POS is optimized for speed.

The user should be able to:

- search quickly
- add products quickly
- review totals
- select customer
- select payment
- complete sale

without unnecessary navigation.

---

# 5. Feedback

Every important action should provide feedback.

Examples:

- Vente enregistrée
- Paiement enregistré
- Produit ajouté
- Produit supprimé
- Stock ajusté
- Synchronisation terminée
- Synchronisation échouée

---

# 6. Destructive Actions

Destructive actions require confirmation.

Examples:

- refund
- cancellation
- inventory adjustment
- user deactivation

---

# 7. Financial Information

Financial information must be clearly formatted.

Use consistent:

- currency formatting
- decimals where appropriate
- positive/negative states
- totals

---

# 8. Statuses

Use consistent statuses.

Examples:

- Actif
- Inactif
- Disponible
- Vendu
- Réservé
- En attente
- Payé
- Partiellement payé
- En retard
- Remboursé
- Annulé

---

# 9. Forms

Forms should:

- group related information
- show required fields
- validate clearly
- preserve entered data when possible
- explain errors

---

# 10. Tables

Tables should be optimized for operational scanning.

Prioritize:

- important identifiers
- status
- amounts
- dates
- actions

---

# 11. Empty States

Empty states should explain what the user can do next.

Example:

"Aucun produit enregistré.

Commencez par ajouter votre premier produit."

---

# 12. Error States

Error messages should:

- explain what happened
- avoid technical jargon
- suggest next action where possible

---

# 13. Offline UX

Offline mode must be explicit.

Never make the user guess whether a transaction has synchronized.

---

# 14. Accessibility

Follow accessible UI principles.

Important actions must be usable with keyboard navigation where appropriate.

---

# 15. Consistency

Equivalent actions should behave and look similarly throughout the application.
